# Resume privacy and processing

Uploads are optional, private and account-scoped. Only authenticated APIs accept a raw PDF/DOCX body; CSRF and operation rate limits apply. Default maximum is 5 MiB (`RESUME_MAX_BYTES`, configurable up to 10 MiB). Bytes are bounded while streaming; media type, file signature and content structure are checked. Original filename is reduced to a safe basename; actual storage uses a server-generated 32-hex identifier, never a user path. Storage is ignored by Git and is not mounted as static content. Explicit absolute `RESUME_STORAGE_PATH` is supported; otherwise storage is beside the authentication database.

PDF processing uses the already-installed pypdf: encrypted documents and more than twenty pages are rejected; text is bounded. DOCX parsing rejects oversized expanded archives (>10 MiB), more than 300 members, embedded VBA and XML entities/DOCTYPE. Files are not executed. Extraction runs in a separate Python process with a ten-second timeout and captured (not emitted) diagnostics. No resume goes to an AI API, analytics service or external parser. There is no OCR. OS-enforced memory quotas, antivirus/content-disarm scanning and production worker concurrency limits are not implemented; deploy those before accepting untrusted uploads at scale.

Extraction is deliberately conservative: explicit Skills/Education/Experience headings, bounded candidate lists, no guessed ontology, sensitive-trait inference or fabricated verification. English labelled-section detection is implemented; nonmatching/local-language layouts may yield incomplete candidates. Scanned PDFs return an honest no-readable-text state. Full extracted text is not retained, only limited candidate metadata.

Candidates remain proposals until the user selects/edits/removes and confirms them. Confirmed fields carry `RESUME_DERIVED` with the private resume ID. Download checks current owner/session, uses an attachment response and no-store/nosniff; there is no public file URL. Replacing a resume commits new metadata/derived-field cleanup before unlinking the old file, preserving it if the database transaction fails. Deletion removes active metadata, file and linked resume-derived education/skills/experience; independently edited self-reported information is retained.

SQLite and private local files are not encrypted by this application. Deployment must secure filesystem permissions, volumes and backups. Files persist until replace/delete; timed retention and full account deletion/export are future work. A crash or filesystem failure between DB commit and unlink may leave an inaccessible orphan requiring reconciliation. There is no claim of complete compliance certification or production malware protection.

Tests use a synthetic DOCX and a generated blank PDF, not personal documents. No resume text, credentials or OTP are captured in browser result logs.
