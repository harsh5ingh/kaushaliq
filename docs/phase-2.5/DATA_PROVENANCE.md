# Evidence and analytical boundaries

Each observation/reference links to a registered publisher/publication/version, original immutable byte hash, retrieval receipt, table/page/row/cell locator and transformations. The canonical manifest binds these inputs. The API returns per-record evidence and exposes source metadata. The frontend **View evidence** dialog shows source link, publisher, period, version, coverage, methodology, receipt date, transformations, limits, reuse terms and hash. Information is in the product, not just documentation.

PLFS table16/17/18 state national rows are compared to PIB table1/2/3 before publication. Distinct sources supply state and national records; identical national metric identities are not duplicated. PDF page numbers distinguish PDF page125 from printed A-62. Percentage parsing does not create new statistical meaning.

Public metadata is retained in its published language; UI labels/caveats are English/Hindi. Do not present a machine translation of a taxonomy as an official classification.

No derived labour metric is published. Filtering, hierarchy normalization and charting are transformations of observed records, not new demand/gap/forecast estimates. Training state sums are a quality check, not replacement national statistics. Counts and rates, FY and July–June periods, vacancy posts and employed persons cannot be casually subtracted.

All production-default views use OBSERVED or UNAVAILABLE. Legacy sample mode remains explicit with its prior simulation disclosures; public homepage conceptual visuals are preserved as conceptual. There is no automatic sample fallback and no sample observation in the canonical API.

Future gap methodology must establish compatible geography, time, population, units and taxonomy before subtraction. Future predictions require historical sufficiency, comparable frequency/design, missingness strategy, evaluation and uncertainty. Future AI responses must cite these evidence objects and refuse unsupported labour statistics.
